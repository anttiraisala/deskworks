### 2026-10-18: tilepane editor: a typed command is not lost when the next click goes elsewhere
- Reported by the owner: a command typed into the `run` field of a pane is empty after selecting another pane and the same pane again. Cause (as far as it could be found without the owner's browser, which is Firefox judging by an earlier screenshot): fields commit on the `change` event, which comes when the field loses focus. Clicks on a pane, the monitor or a line start with `preventDefault()` on pointerdown, and a render that follows removes the focused field; Firefox then gives no `change` and the text is gone. Chromium, which the tests use, commits on removal, so the loss itself could not be reproduced there.
- What did fail in Chromium and is fixed: typing and then clicking a button of the panel (for example "Cut pane") lost the button's click, because the commit that the loss of focus triggers rendered a new panel under the pointer before the mouse button went up.
- Fix: `flushFields()` makes the focused input or textarea lose focus (so the commit runs) at the capture phase of every pointerdown and at the start of undo, redo, save and "open on screen"; `render()` is held back while it runs (`S.holdRender`) and done when the pointer goes up (`S.renderPending`). The commit uses the path of its own pane, not the current selection.
- Tests: three scenarios in `tests/js/editor.features.mjs` (a synthetic mouse down and up that moves no focus, a real click on another pane, a click on a button which must still work, a click outside the monitor, Ctrl+Z after typing). The button scenario fails without the fix; the others pass in Chromium either way and guard the behaviour. tilepane 344 pass (5 skipped). Not verified in Firefox or on the owner's machine; if the command still disappears there, the owner should tell which steps lose it.

### 2026-10-18: tilepane `--analyze`: a layout from the open windows
- Requested by the owner: the opposite of opening a layout. `tilepane --analyze [FILE]` reads the windows that are open on a monitor and writes a layout file; `--edit` with it opens the editor on the file. Options: `--monitor` (default: the monitor of the active window, else the pointer; a list or `all` give one layout each), `--workspace current|N|all`, `--terminals-only`, `--dry-run` (the file to the standard output, the report to the standard error), `--yes` (replace an existing file; default file `analyzed-layout.json`).
- Overlapping windows (the owner's question, decided as the owner proposed): the layout gets splits where needed so that the panes do not overlap. `analyze.derive` makes guillotine cuts: first cuts that cross no window, otherwise the cut between the window centres that takes the least area, each window keeps the part on its side; windows with the same centre are put in equal strips. The report gives the largest difference in pixels. Gaps up to 12 px and overlaps up to 6 px count as noise because terminals sit on character cells; `margin` is the median gap, `outer_margin` is set only when the outer distance differs from the margin's half; screen that no window covers becomes empty panes.
- Panes: terminals get the command found in `/proc` (`processes.py`; a window that tilepane opened gives back its commands, directory, title and `on_exit` from the runner's command line; a gnome-terminal server shared by several windows gives nothing); other windows become a shell titled `<class>: <title>`.
- deskmap: `Backend.open_windows()` (new `OpenWindow` type), `active_window()` and `pointer()` in the X11 backend; on Compiz a window's rectangle is given in the coordinates of its own viewport.
- Tested: 36 new unit tests (`tests/test_analyze.py`: exact round trips of random layouts with several margins, noise, overlaps, `/proc` parsing with a fake tree, the command line, the whole command with a fake backend); a live test (`test_x11_live`) opens three xterm windows through tilepane, lists them and derives the same layout with the commands `sleep 30/31/32` back. By hand in Xvfb + openbox: the demo's six windows gave a layout with margin 14, outer margin 6 and a largest difference of 12 px (xterm's character cells). tilepane 381 pass (6 skipped without a display). Not verified on the owner's machine, with gnome-terminal or with Compiz viewports.
- Open ideas: a pane for every window of a cascade keeps only a share of it; the stacking order is not used to decide who wins an overlap; non-terminal windows cannot be started by tilepane, so they stay placeholders; `--capture` of the commands of gnome-terminal windows needs a way to find the terminal's tty per window.
